# Анализ: текущее состояние и проблемы

## Как сейчас

- Позиция заметки — файл `N_state`: `x;y;color;width;height;fontSize;` (`_saveState`/`_loadState`, noteBox.js). `N_text` — текст.
- `_x/_y` относительны primary-монитора: `_setNotePosition` = `primaryMonitor.x + _x`.
- Монитор в состоянии не сохраняется; на `monitors-changed` расширение не подписано.
- `_loadAllNotes` (extension.js) считает заметки пробегом `0_state, 1_state, …` до первого пропуска — id плотные 0..N-1.
- `postDelete` при удалении переставляет последнюю заметку на место удалённой (`lastNote.id = deletedNoteId`) и перенумеровывает файлы.
- Спасение «заэкранных» заметок — `fixState`: проверка границ primary с полем 20px, случайное перемещение `_computeRandomPosition`. Вызывается только кнопкой «Bring back to the primary monitor» (переключение gsettings-ключа `ugly-hack`).

## Проблемы

1. Отключили второй монитор → заметки за экраном: невидимы, некликабельны, но продолжают сохраняться с теми же координатами.
2. Проверка `fixState` смотрит только левый-верхний угол: заметка на `x = width - 30` считается «в границах».
3. Random-перемещение непредсказуемо — ручная корректировка каждый раз заново.
4. Нет памяти о конфигурациях: раскладку «на два монитора» негде хранить.

## Неучтённые моменты (учесть в решении)

- **Нестабильные id.** Swap в `postDelete` ломает любые внешние ссылки на заметки (в т.ч. будущие раскладки) — нужны стабильные id без переиспользования.
- **Смена primary при той же геометрии** — все заметки прыгают, пока координаты относительные.
- **Шторм `monitors-changed`** при горячем подключении: промежуточные конфигурации не должны попадать в реестр (вытеснят полезные схемы) — debounce + сравнение сигнатуры.
- **Политика LRU:** «свежесть» = использование, не только правка; иначе активно используемая, но не правимая схема вытеснится.
- **Единый реестр = единая точка отказа** — атомарная запись + `.bak` + откат при порче.
- **Текст ≠ метаданные:** текст в общем JSON переписывал бы реестр целиком на каждое сохранение.
- **Заметки, отсутствующие в старой схеме** (созданы позже) — правило размещения при применении схемы.
- **Масштабирование/Wayland:** использовать только логическую геометрию `Main.layoutManager.monitors`.
- **Заметка крупнее монитора** — клампить размеры.
- **UI-хвосты:** строка prefs.ui про `_state`-файлы устареет; кнопка «Bring back…» меняет семантику.
- **Гонка «смена мониторов во время drag»** — применять раскладку после release.
- Осознанное ограничение: сигнатура по геометрии не различает рабочие места с одинаковыми мониторами.
