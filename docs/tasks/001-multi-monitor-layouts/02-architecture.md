# Концепция архитектуры

Решение зафиксировано в [ADR-0001](../../adr/0001-multi-monitor-layout-registry.md). Ниже — конструктив.

## Координаты

Глобальные координаты сцены. `_setNotePosition` применяется без offset primary; `_moveTo`/`_resizeTo` уже работают в координатах событий (глобальных) — не меняются.

## Сигнатура конфигурации мониторов

```
monitors → ["WxH+X+Y", …] → sort → join(",")
```

Логическая геометрия (`Main.layoutManager.monitors`). Примеры:

```
"1920x1080+0+0"                     — только ноутбук
"1920x1080+0+0,1920x1080+1920+0"    — ноутбук + офисный монитор
"1920x1080+0+0,2560x1440+1920+0"    — ноутбук + домашний монитор
```

Сортировка делает ключ каноническим (порядок перечисления мониторов не важен). Ключи человекочитаемы — легко дебажить.

## Реестр `layouts.json` (DATA_PATH)

```json
{
  "version": 1,
  "seq": 12,
  "notes": {
    "7": { "color": "sky", "fontSize": 12 }
  },
  "layouts": {
    "1920x1080+0+0,2560x1440+1920+0": {
      "savedAt": 1760000000000,
      "positions": {
        "7": { "x": 2100, "y": 120, "w": 250, "h": 180 }
      }
    }
  }
}
```

- `seq` — счётчик стабильных id (не переиспользуются, swap удаляется).
- `notes` — атрибуты заметок, не зависящие от конфигурации (цвет, шрифт).
- `layouts[key].positions[id]` — позиция и размер заметки в конфигурации `key`.
- `savedAt` = `Date.now()` (мс). Лимит схем `MAX_LAYOUTS = 8`, вытеснение LRU.
- Запись: `GLib.file_set_contents` (атомарно, temp+rename) + ротация `.bak` (предыдущая хорошая версия). Чтение: невалидный JSON → `.bak` → пустой реестр.
- Текст остаётся в `N_text` (id в имени файла = id из реестра; при миграции сохраняются существующие номера файлов).

## Поведение

### Загрузка (enable / показ заметок)

1. `LayoutStore.load()`; если реестра нет — миграция из `N_state` (см. ниже).
2. Сигнатура текущей конфигурации; позиции из `layouts[key]` (клампинг как страховка) либо fold.
3. Схема текущей конфигурации touch'ится и сохраняется.

### Смена мониторов (`monitors-changed`)

1. Debounce ~1 c; применять только если сигнатура изменилась.
2. Есть схема для новой сигнатуры → применить: позиция из схемы, если заметка в ней есть и видима; заметок без записи в схеме — текущая позиция, если видима, иначе fold-слот.
3. Нет схемы → fold только заметок вне объединения мониторов (видимые не трогаем) → результат сохраняется как новая схема, LRU-вытеснение при переполнении.

### Fold (детерминированный, O(n))

Заметки в порядке id, каскад от левого верхнего угла primary: шаг 24×24 px, при выходе за ширину — следующая строка, за высоту — сброс наверх со сдвигом отступа; `w/h` клампятся к размеру монитора (мин. `MIN_WIDTH`/`MIN_HEIGHT` сохраняются). Без случайности: повторные сборы кладут заметки в те же места.

### Сохранение

- Release после drag/resize, смена цвета/шрифта → менеджер собирает позиции всех заметок → `store.put(currentKey, positions)` — одна атомарная запись.
- Скрытие заметок, `disable` → финальный flush реестра.
- Текст — как сейчас (`_saveText`), без изменений.

### Кнопка «Bring back to the primary monitor»

`foldAllIntoPrimary()`: fold всех заметок в primary в любой конфигурации + сохранение схемы. Канал prefs→extension прежний: тоггл gsettings-ключа `ugly-hack`.

### Миграция из `N_state` (однократно)

- Пробег `0_state, 1_state, …`; каждому — стабильный id = номер файла (имена `N_text` не меняются), `seq` = количество.
- Координаты: `x += primary.x`, `y += primary.y` (origin передаётся параметром — модуль не знает про shell).
- Legacy-поле 7 (`entry_is_visible`) игнорируется; NaN/мусор → дефолты.
- Результат пишется как схема текущей конфигурации. Старые `_state`-файлы не удаляются в миграции (естественный бэкап); удаление — отдельный шаг после приёмки.

## Модули

| Модуль | Роль |
|--------|------|
| `layouts.js` (новый) | Сигнатура, `LayoutStore` (load/save/.bak/get/put/touch/removeNote/nextId/миграция), fold-расчёт, клампинг. Без Clutter/St — тестируется gjs вне shell. |
| `extension.js` | Владелец store; `monitors-changed` + debounce; `applyLayoutForCurrentConfig()`; `foldAllIntoPrimary()`; сборка позиций при сохранении. |
| `noteBox.js` | Глобальные координаты; атрибуты и позиция из менеджера; `onlySave` → менеджер; удаление `_loadState/_saveState/_createDefaultState/fixState/_computeRandomPosition/areCoordsUsable`. |
| `common.js` | `MAX_LAYOUTS = 8` (константа). |
| `prefs.ui` / `prefs.js` | Обновление текста про `_state`-файлы; кнопка без изменений (семантика = fold). |

## Производительность

Один read+parse на загрузку (< 1 мс на реалистичных объёмах: 8 схем × ~100 заметок ≈ десятки КБ). В памяти два словаря. O(n) на смену конфигурации. Единственный таймер — debounce. Зависимости: `GLib`/`Gio` + нативный `JSON`.
