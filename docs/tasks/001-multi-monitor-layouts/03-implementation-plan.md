## Ф1. Модуль `layouts.js` + юнит-тесты

Чистая логика, вне shell. Аддитивно, поведение расширения не меняется.

**Новый файл `notes@maestroschan.fr/layouts.js`:**

```js
signature(monitors)            // [{x,y,width,height}] → "WxH+X+Y,…" (sort, join)
clampRect(rect, monitors)      // вписать в пересекающийся монитор; oversized → ужать
foldInto(monitor, notes, occupied) // детерминированный каскад; notes: [{id,w,h}]
                               // в порядке id; occupied — уже занятые прямоугольники

class LayoutStore {
    constructor(filePath)      // путь к layouts.json передаётся (тестопригодность)
    load()                     // parse → валидация → .bak → пустой реестр
    save()                     // GLib.file_set_contents (атомарно) + ротация .bak
    layoutFor(key)             // {savedAt, positions} | null
    put(key, positions)        // запись + LRU-вытеснение до MAX_LAYOUTS + save
    touch(key)                 // обновить savedAt + save
    removeNote(id)             // из notes и всех layouts + save
    nextId()                   // seq, без переиспользования
    setNoteAttrs(id, attrs) / getNoteAttrs(id)
    noteIds()
    migrateFromStateFiles(dir, origin, currentKey)
                               // dir: DATA_PATH; origin: {x,y} primary;
                               // currentKey: сигнатура текущей конфигурации
}
```

- `MAX_LAYOUTS = 8` — в `common.js` (единое место констант).
- Валидация при `load()`: числа, `w/h ≥ MIN`, sane-диапазоны; мусорная запись заметки → дефолт, мусорный файл целиком → `.bak`.
- Миграция: пробег `0_state, 1_state, …` до пропуска; id = номер файла (имена `N_text` не меняются); `x += origin.x, y += origin.y`; legacy-поле 7 игнорируется; NaN → дефолт. Записывает схему `currentKey` + атрибуты `notes`.

**Новый файл `test/testLayouts.js`** (запуск из корня репо: `gjs test/testLayouts.js`, подключение через `imports.searchPath`). Покрытие:

- сигнатура: инвариантна к порядку мониторов; разные геометрии → разные ключи;
- put/LRU: 9-я схема вытесняет старейшую по `savedAt`; `touch` обновляет свежесть;
- миграция: relative→global, legacy-поле, NaN→дефолт, плотность id;
- порча JSON → `.bak` → пустой реестр;
- fold: детерминизм (повторный вызов — те же слоты), в границах монитора, не наезжает на `occupied`;
- clamp: втянутая в монитор позиция; oversized-заметка ужата.

**Проверка:** `gjs test/testLayouts.js` зелёный; расширение не затронуто.

## Ф2. Переключение хранения: реестр + стабильные id + глобальные координаты

Один cutover-коммит (хранение/координаты/миграция неразделимы).

**`extension.js`:**

- Конструктор: создать `LayoutStore(layouts.json)`, `load()`; реестра не было → `migrateFromStateFiles(PATH, {primary.x, primary.y}, signature(monitors))`. Кэш `this._currentKey`.
- `_loadAllNotes`: перечисление из `store.noteIds()` вместо пробега по файлам.
- `createNote`: `id = store.nextId()`; для новой заметки `setNoteAttrs(id, {color, fontSize})`; позиции для новой заметки — fold-слот в primary (замена `_computeRandomPosition`/`areCoordsUsable`).
- `postDelete(id)`: `store.removeNote(id)` + удаление только `N_text`; swap-логика удаляется.
- Новый `saveLayout()`: собрать `{id: {x,y,w,h}}` из `_allNotes` → `store.put(this._currentKey, …)`.
- `destroy()`: финальный `store.save()` (тексты сохраняются как сейчас, `onlySave(false)`).
- `areCoordsUsable` — удалить. Обработчик `ugly-hack` — временно no-op (комментарий: включается в Ф3).
- Подписка `monitors-changed` тоже ставится здесь (см. Ф3-логику), handler до загрузки заметок — no-op.

**`noteBox.js`:**

- Конструктор получает от менеджера `{id, color, fontSize, x, y, w, h}` (позиция — из схемы или fold-слот, решает менеджер).
- `_setNotePosition`: без `primaryMonitor`-offset — `set_position(floor(x), floor(y))`.
- `onlySave(withMetadata)`: текст как сейчас; `withMetadata` → `manager.saveLayout()` (одна запись на все заметки).
- Удалить: `_loadState`, `_saveState`, `_createDefaultState`, `fixState`, `_computeRandomPosition`, чтение `_state`-файлов.
- `_moveTo`/`_resizeTo` — без изменений (координаты событий уже глобальные).

**Проверка (дым, реальная сессия):** существующие заметки после обновления на местах (миграция); drag/resize/hide/show/цвет/шрифт пишут только `layouts.json` + `N_text`; `N_state` больше не читаются и не пишутся; удаление заметки чистит реестр; повторный enable/disable идемпотентен.

## Ф3. Реакция на смену мониторов + fold

**`extension.js`:**

- `monitors-changed` → debounce 1000 мс (`Mainloop.timeout_add`, источник сбрасывается) → пересчитать сигнатуру; не изменилась → выход.
- `applyLayoutForCurrentConfig()`:
  1. заметки с записью в схеме: применить позицию, прогнав через `clampRect` (страховка от изменившейся геометрии);
  2. заметки без записи: текущая позиция, если видима (в объединении мониторов), иначе — fold-слот (`occupied` = прямоугольники из шага 1);
  3. результат → `store.put(newKey, …)`.
- Кнопка «Bring back to the primary monitor» (`ugly-hack`): `foldAllIntoPrimary()` — fold всех заметок в primary + `saveLayout()`. Работает в любой конфигурации.
- `destroy()`: disconnect `monitors-changed`, отмена висящего debounce.

**Проверка (дым):** отключить/подключить второй монитор в живой сессии — сбор и восстановление; повторные быстрые переключения — одна применённая раскладка (дебаунс); кнопка собирает всё в primary.

## Ф5. Приёмка и деплой

**Обязательная предтестовая копия:** бэкап `~/.local/share/notes@maestroschan.fr`.

Матрица приёмки:

| # | Сценарий | Ожидание |
|---|----------|----------|
| 1 | 2 монитора: разложить, скрыть/показать, перезапуск shell | позиции сохранены точно |
| 2 | отключить 2-й монитор | невидимые заметки собраны каскадом в primary; видимые не тронуты; создана схема «1 монитор» |
| 3 | правка на 1 мониторе, подключить 2-й обратно | восстановлена схема шага 1 |
| 4 | чередование 3 конфигураций (стори README, шаги 1–6) | точное восстановление своей схемы каждой конфигурацией |
| 5 | быстрые повторные переключения мониторов | один apply по итоговой конфигурации; мусорных схем нет |
| 6 | заметка создана в конфигурации B, разложена; переход в A | в A — fold-слот (или видимая текущая), в B — своя позиция |
| 7 | удаление заметки | исчезла из реестра и всех схем; id не переиспользованы |
| 8 | порча `layouts.json` | загрузка из `.bak`; без `.bak` — пустой реестр, заметки с дефолтами |
| 9 | миграция на копии реальных данных | координаты совпали, тексты на месте, `_state` не тронуты |
| 10 | Wayland-сессия | пункты 1–3 работают (X11 — харнесс `:1` + реальная сессия) |

- Деплой `install.sh`, проверка на установленной копии.
- Отдельное решение после приёмки: удалять ли старые `_state`-файлы (в миграции не удаляются).

## Риски и открытые вопросы

- `monitors-changed` на Wayland/X11 вызывается в разном темпе — debounce 1000 мс снять/подкрутить по факту тестов.
- Ленивая загрузка заметок (`_notesLoaded`): handler смены мониторов обязан быть no-op до первой загрузки — иначе применять нечего.
- Синхронная миграция на enable: файлы крошечные, блокировка не ожидается; замерить при сотне заметок.
- Клавиатурный focus/перетаскивание во время смены мониторов: применять раскладку только вне активного drag (`_isMoving/_isResizing`).
