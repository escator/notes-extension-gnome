## Журнал

- **2026-10-23, Ф2.** Ядро NoteBox готово. Детектор двойного клика в
  `_onMovePress` (кнопка 1, Δt ≤ `Clutter.Settings.double_click_time`
  fallback 400 мс, Δ≤8px; каждое нажатие обновляет трекер; второй —
  `_toggleExpanded()` + EVENT_STOP, `_isMoving` сбрасывается — первое
  нажатие пары его уже взвело). Замер `_neededH(W)` по текущей аллокации
  (chromeW/H от clutterText, `get_preferred_height(W−chromeW)[1]`), no-op
  при `_isTextFullyVisible()` (+2px). Разворот: `_homeRect` = живой
  прямоугольник до применения цели, пол поиска `max(live.w, home.w)`
  (ручные расширения re-fit не откатывает). `_applyRectAnimated`:
  бухгалтерия (`_x/_y`, `_targetW/H` округлённые) — сразу, актор —
  `ease` 250 мс EASE_OUT_QUAD со снапом в onComplete; нажатие посреди
  анимации (`_onPressCommon`) — `remove_all_transitions` + снап к
  бухгалтерии. `show()` сворачивает мгновенно до видимости. Re-fit в
  `_onTextChanged`/`changeFontSize` без анимации. Прогон: layouts 82/82,
  дым 83/83, textHistory 51/51.
  **Отступление от буквы плана (в согласии с архитектурой §1):** в
  `_onRelease` home переписывается только после реального drag/resize —
  флаг `_gestureMoved` (взводится в `_moveTo`/`_resizeTo`). Буквальное
  «при `_expanded` — home = живой» ломало сценарий 2: релиз двойного
  клика или пустой клик по шапке сделали бы развёрнутый прямоугольник
  домашним, и сворачивание стало бы no-op. Заодно это страхует home от
  промежуточных размеров летящей анимации. Персистенс менеджера ещё
  старый: развёрнутый размер может попасть в layouts.json до Ф3 —
  осознано, проверки диска после Ф3. Дым не затронут (фейковый NoteBox).

- **2026-10-23, Ф1.** Чистая геометрия в layouts.js, поведение расширения не
  менялось. `bestMonitor` извлечён из тела `clampRect` (пустой список →
  null, вне мониторов → первый), `clampRect` переписан на него — старые
  тесты зелёные без правок. Новый `fitExpandRect(baseRect, monitors,
  neededH)`: пол поиска `min(baseRect.w, monitor.width)`, шаг 40px при
  условии `neededH(W) ≤ min(4/3·W, monitor.height)`, защита A (нигде не
  влезает → W = ширина монитора), защита B (H = min(4/3·W, monitor.height),
  пропорция сознательно ломается), сдвиги влево/вверх через `_clamp` у
  краёв. Тесты: 13 новых проверок (bestMonitor 4, fitExpandRect 9) по
  образцу существующих; нюанс — ожидания с 4/3 в тестах должны считаться
  тем же выражением, что и в коде (`4 / 3 * w`), иначе JSON-сравнение
  ловит разницу double в последнем бите. Прогон `gjs test/testLayouts.js`:
  82/82.
