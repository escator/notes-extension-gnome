# 01: Анализ — разворачивание заметки двойным кликом

Контекст решения: скроллинг отвергнут из-за бага natural-size; выбран
toggle-разворот по двойному клику. Решения пользователя от 2026-10-23 — в
[02-architecture.md](02-architecture.md).

## 1. Текущее устройство заметки (noteBox.js)

- Внешний актор — `St.BoxLayout` с фиксированными `width/height`
  (noteBox.js:84–96), хром через `Main.layoutManager.addChrome`.
- Шапка `_buttonsBox` содержит moveBox — «пустое» место для перетаскивания
  (noteBox.js:290–295). Обработчики: `button-press-event` → `_onMovePress`,
  `motion-event` → `_onMoveMotion`, `button-release-event` → `_onRelease`
  (noteBox.js:312–314). Перетаскивание стартует только при движении
  (`_isMoving` + `grabX/grabY`), у двойного клика движения нет — конфликт
  минимален.
- Текст: `St.Entry` (`noteEntry`) внутри `_entryBox` внутри `St.ScrollView`
  с `clip_to_allocation: true` (noteBox.js:103–120). Контент за пределами
  окна просто обрезается — скролла нет.
- `show()` (noteBox.js:739) — единственная точка появления заметки на экране
  (глобальный toggle, сброс фильтра) — место для правила «показ → домашний
  размер».

## 2. Почему нативный скролл не работает (контекст, не реализуем)

Root-сводка по журналу отладки 2026-10-19 (Xephyr, логи alloc/preferred):

- `clutterText.get_preferred_height(W)` даёт **правильный** height-for-width
  (358 → 152) — сломан не расчёт, а распространение;
- unconstrained natural size ClutterText — «одна длинная строка» (лог:
  2631×19 при аллокации 358×22): `St.Entry` — контейнер без layout manager
  (NO_LAYOUT), и при изменении текста Clutter делает shallow relayout по
  natural size;
- контейнеры St считают preferred height от natural width, поэтому
  `_entryBox` сообщает заниженную высоту → `St.ScrollView` видит «всё
  влезает» → vadjustment пуст, колесо инертно;
- отображение спасено фиксацией 368bfb0 (сняты align START, entry FILL'ит
  окно), переполнение клипается.

Выводы для задачи 005: (а) явный замер по реальной ширине корректен —
используем; (б) смена фиксированного размера верхнего актора форсирует
полный deep relayout — используем как рычаг; (в) natural size не трогаем.

## 3. Персистенс: все точки чтения геометрии

Геометрия хранится в `layouts.json` (реестр задачи 001), формат не меняется.
Менеджер снимает размеры **прямо с актора** в пяти местах — любое из них
утечёт развёрнутым размером на диск:

| # | Место | Что читает |
|---|-------|-----------|
| 1 | `saveLayout` (extension.js:295–296) | `n.actor.width/height` — вызывается при каждом клике (`_redraw` → `onlySave`), drag/resize release, смене цвета/шрифта |
| 2 | `createNote`, карта занятых слотов (extension.js:230) | `n.actor.width/height` |
| 3 | `_noteRect` (extension.js:304–311) | `n.actor.width/height` — используется раскладкой monitors-changed (:345, :352, :359) |
| 4 | `applyLayoutForCurrentConfig`, fold-слоты потерянных (extension.js:365) | `n.actor.width/height` |
| 5 | `foldAllIntoPrimary` (extension.js:386) | `n.actor.width/height` |

Писатели геометрии: `_applyRectToNote` (extension.js:313–319, monitors-changed
и «вернуть на основной»), `_resizeTo`/`_moveTo`/`_setNotePosition`
(noteBox.js) — все пишут и актор, и бухгалтерию `_x/_y` синхронно. Это
позволяет не менять бухгалтерию: `_x/_y` всегда живые, «домашний»
прямоугольник хранится отдельно.

`_hideNotes` (extension.js:413–429) вызывает `onlySave(false)` — текст без
раскладки, геометрию при скрытии не пишет; правило «показ → домашний размер»
реализуется в `NoteBox.show()`.

## 4. Двойной клик: API

`clutter_event_get_click_count` / `get_click_count()` нигде не используется
в JS gnome-shell (проверка grep 2026-10-23) — заполнение click_count не
гарантировано. Детектирование ручное: та же кнопка, Δt ≤ double-click-time
(`Clutter.Settings`, попробовать с try/catch, fallback 400 мс), Δрасстояние
≤ 8px.

## 5. Мониторы

- `NotesManager._monitorRects()` (extension.js:150–154) — логические
  прямоугольники мониторов; конвенция проекта — прямоугольник монитора
  **без** workarea-отступов (заметки — chrome, панель не мешает; так же
  работает `clampRect`).
- Выбор «своего» монитора по максимальному пересечению — логика уже есть
  внутри `Layouts.clampRect` (layouts.js:59), её следует извлечь в
  экспортируемый `bestMonitor` и переиспользовать.
- Проверено `testLayouts.js` — чистые функции layouts.js покрываются
  юнит-тестами без shell: алгоритм подбора развёрнутого прямоугольника
  стоит сделать такой же чистой функцией.

## 6. Неучтённые моменты (закрыты решениями 2026-10-23)

- Фокус не нужен вовсе: разворот — реакция на клик, не на колесо/клавиатуру;
  hover-фокус из первоначальной идеи скроллинга выпадает (он и был
  сознательно отключён ранее, ветка auto-focus).
- Формат данных не меняется; позиция разворота нигде не персистится.
- Новых строк UI/переводов нет — каталог не трогаем.
- Read-only-проглатывание кликов (f051d89) касается только текста,
  moveBox всегда реактивен — оба режима работают одинаково.
