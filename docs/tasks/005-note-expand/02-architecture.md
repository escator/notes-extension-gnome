# 02: Архитектура — разворачивание заметки двойным кликом

Решения пользователя от 2026-10-23 (согласованы в обсуждении, см. ADR-0004):

1. Разворот вместо скроллинга — чтобы не связываться с багом natural-size.
2. Пропорция развёрнутой формы **3:4** (высота = 4/3 ширины, портретная) —
   эстетика, против «слишком длинных» окон; заметка растёт не только вниз,
   но и в ширину (текст перепаковывается на большей ширине).
3. Рост: вниз от текущего `y`, при нехватке места — сдвиг вверх; ширина —
   вправо от левого края, у правого края монитора — сдвиг влево.
4. Если весь текст уже виден — двойной клик ничего не делает.
5. Домашний размер: развёрнутый размер не сохраняется; ручной resize в
   развёрнутом виде сохраняется по обычному пути; сворачивание возвращает к
   последнему ручному размеру (если ручного не было — к размеру до
   разворота).
6. Скрыть заметки в развёрнутом виде → при следующем показе стартовый
   (домашний) размер.
7. Разворот/сворачивание анимируются.
8. Максимум — это **защита**, а не штатный режим (см. §4).

## 1. Модель home-rect (персистенс)

Состояние NoteBox:

- `this._expanded = false`;
- `this._homeRect = null` — снимок `{x, y, w, h}` на момент разворота.

Правила:

- Бухгалтерия `_x/_y` и размеры актора остаются **всегда живыми** (как
  сейчас): drag/resize в развёрнутом виде считают от фактической геометрии,
  писатели не меняются. Домашний прямоугольник — отдельный снимок.
- `getPersistedRect()` (публичный): развёрнута → `_homeRect`, иначе —
  живой `{x: _x, y: _y, w: actor.width, h: actor.height}`. **Единственный**
  источник геометрии для менеджера при сохранении (все 5 точек чтения из
  01 §3).
- Разворот: до применения целевого прямоугольника `_homeRect = живой`.
- `_onRelease` (конец drag/resize) при `_expanded`: `_homeRect = живой` —
  ручной размер становится домашним и персистится по обычному пути (решение
  п. 5).
- Сворачивание: цель = `_homeRect`, сброс `_expanded/_homeRect`.
- `show()`: если развёрнута — свернуть мгновенно (п. 6; путь фильтра и
  глобального toggle проходит через show).
- `_applyRectToNote` (менеджер): перед записью прямоугольника свернуть
  развёрнутую заметку мгновенно — monitors-changed и «вернуть на основной»
  несут раскладку домашней геометрии.

Инвариант: на диске всегда лежит домашняя геометрия; развёрнутый размер
существует только на экране.

## 2. Двойной клик

Детектирование в `_onMovePress` (noteBox.js): нажата та же кнопка 1, Δt от
предыдущего нажатия ≤ double-click-time (`Clutter.Settings` в try/catch,
fallback 400 мс), Δкоординат ≤ 8px. На втором нажатии — `_toggleExpanded()`,
`Clutter.EVENT_STOP` (drag не стартует, `_isMoving` не взводится). Первое
нажатие пары проходит обычный путь (`_onPressCommon` → redraw; безвредно:
персистенс идёт через `getPersistedRect`).

Состояние детектора: `_lastPressTime`, `_lastPressX/_lastPressY` — поля
NoteBox.

## 3. Алгоритм разворота (замер + подбор прямоугольника)

Замер (noteBox.js, по текущей аллокации — обходит баг natural-size):

- `chromeW = actor.width − clutterText.width` (бордеры),
  `chromeH = actor.height − clutterText.height` (шапка + бордеры);
- `neededH(W) = chromeH + clutterText.get_preferred_height(W − chromeW)[1]`
  — высота актора, на которой текст ширины `W` виден целиком;
- no-op: `neededH(actor.width) ≤ actor.height + 2` → разворачивать нечего
  (решение п. 4).

Подбор прямоугольника — чистая функция `Layouts.fitExpandRect(baseRect,
monitors, neededH)` в layouts.js (юнит-тестируемая, без shell):

1. монитор = `bestMonitor(baseRect, monitors)` — максимальное пересечение
   (логика извлекается из `clampRect`);
2. пол поиска `w₀ = min(baseRect.w, monitor.width)`;
3. поиск вверх от `w₀` шагом 40px минимальной ширины `W`, при которой
   `neededH(W) ≤ min(4/3·W, monitor.height)`;
4. позиция: `x = baseRect.x`, при `x + W > monitor.right` — сдвиг влево,
   `x ≥ monitor.x`; `y = baseRect.y`, при `y + H > monitor.bottom` — сдвиг
   вверх, `y ≥ monitor.y` (решение п. 3).

Примечание: на каждом шаге поиска pango-замер дешёв (без аллокации);
шаг 40px достаточно мелкий, чтобы «минимальность» не разбухала, и крупный,
 чтобы замеров было мало.

## 4. Ограничение максимума (защита)

Штатно потолок не срабатывает: обычно текст влезает в 3:4-прямоугольник
заметки много меньше экрана. Правила потолка на случай «заметка больше
экрана»:

- **Защита A (ширина)**: `W ≤ monitor.width`. Если текст не влезает и при
  ширине монитора — `W` фиксируется на ширине монитора.
- **Защита B (высота)**: `H = min(4/3·W, monitor.height)`. Если высота
  обрезана монитором — пропорция 3:4 **сознательно нарушается** в пользу
  вмещения: защита важнее эстетики.
- **Крайний случай**: заметка разворачивается до полного прямоугольника
  монитора; если текст не влезает и в него — хвост остаётся скрытым
  (возвращаться к скроллингу — отдельной задачей). Это разовая защита, не
  штатный режим.
- Пол поиска уже ограничен: `w₀ = min(baseRect.w, monitor.width)` — заметка
  с унаследованной шириной больше монитора не расширяется сверх него.
- Сдвиги позиции (§3 п. 4) никогда не выводят края за пределы монитора.

## 5. Re-fit в развёрнутом виде

Изменение контента/стиля при `_expanded` → пересчёт цели по §3 и мгновенное
(без анимации) применение. Триггеры: `_onTextChanged` (набор, вставка,
undo/redo — все идут через set_text), `changeFontSize`. Пол поиска — от
`_homeRect.w` (ручные расширения не откатываем). Если текст стал влезать в
домашнюю высоту — цель остаётся ≥ `homeRect` (сужать заметку под текст не
нужно: свернётся двойным кликом).

**Живая проверка (2026-10-23, приёмка Ф4): пересчёт не происходит
(README-сценарий 8 — «нет»); отклонение принято пользователем сознательно.**
Механизм в коде оставлен как есть; причина не срабатывания не выяснялась
(кандидаты: замер `get_preferred_height` отстаёт от set_text на кадр —
известный риск из 03-плана). Возврат к вопросу — отдельной задачей, если
поведение надоест.

## 6. Анимация

- `_applyRectAnimated(rect, animated)`: бухгалтерия `_x/_y` и целевые
  размеры применяются **сразу**, визуально — `actor.ease({ width, height,
  x, y, duration: 250, mode: EASE_OUT_QUAD, onComplete: снап к целым })`.
- Любое нажатие (`_onPressCommon`) посреди анимации:
  `actor.remove_all_transitions()` + снап актора к бухгалтерии (паттерн
  `cancelFadeOut`, noteBox.js:784) — drag/resize всегда стартуют с факта.
- `show()` и `_applyRectToNote` сворачивают **мгновенно** (появление и
  раскладка — не место для анимации).
- Re-fit — мгновенный (иначе каждый символ дёргал бы анимацию).

## 8. Сброс размера двойным кликом по кнопке resize (дополнение 2026-10-23)

Двойной клик по кнопке изменения размера — быстрый способ уменьшить
выросшую заметку: размер возвращается к стартовому (DEFAULT_WIDTH ×
DEFAULT_HEIGHT, как у новой заметки) в текущей позиции, x/y не меняются,
применение анимированное (250 мс, тот же `_applyRectAnimated`). Для
вручную раздутой заметки это единственная осмысленная семантика:
home-rect существует только в развёрнутом виде. Развёрнутый режим этим
завершается (геометрия разворота сознательно брошена, `_expanded/_homeRect`
сбрасываются), результат персистится обычным путём — сохранение по
завершении анимации (`onComplete`-колбэк в `_applyRectAnimated`), чтобы на
диск легла целевая геометрия. Детектор двойного клика один на moveBox и
btnResize (общий трекер нажатий; геометрически кнопки дальше 8px, ложная
пара невозможна; пара потребляется — см. журнал 2026-10-23).

## 9. Отклонённые альтернативы

Полный список с причинами — в ADR-0004; кратко: нативный скролл
`St.ScrollView` (инертен из-за natural-size), ручной translation-скролл
(новый класс ручной геометрии ради того, что разворот даёт дешевле),
hover-фокус (не нужен без скролла; был сознательно отключён ранее).
