# 01 Анализ: клик вне заметок

## Как доходит клик (GNOME 42.9 этой машины, X11)

Проверено по исходникам установленного shell (gresource из
`/usr/lib/gnome-shell/libgnome-shell.so`):

- Стек: `stage → uiGroup → [window_group (окна + фон), top_window_group,
  chrome…]`; заметки — `addChrome` (`noteBox.js:766`), их меню —
  `uiGroup` (`menus.js:38,305`).
- `layout.js _updateRegions()`: на X11 input region оверлея = union
  прямоугольников видимых chrome-актёров (`affectsInputRegion`),
  применяется `global.set_stage_input_region(rects)`.
- Следствие: клик по пустому рабочему столу или по окну приложения до stage
  **не доходит** — X отдаёт его окну под курсором. «Пассивный» перехват
  (`global.stage` capture) на X11 видит только клики по панели и shell-UI,
  то есть не решает задачу.
- На Wayland input region не используется (`!Meta.is_wayland_compositor()`
  в `wantsInputRegion`), клики по пустому месту доходят до stage — но
  пользователь работает на X11, и решение должно работать одинаково.
- `addChrome` вставляет актёр сразу под `top_window_group`; при
  `Main.modalCount > 0` input region вообще сбрасывается (модальный grab).
- Дерево «своих» актёров, клики по которым не должны ничего скрывать:
  заметки (`note.actor`), опции заметки (`NoteOptionsMenu.super_menu.actor`,
  `menus.js:38`), текстовое меню и его якорь (`menus.js:286,305`), значок
  панели + его меню (`extension.js:564-566`), модальные диалоги
  (`dialog.js`, живут в shell-группе модалок и держат grab).

## Проблема

Нужен источник событий «клик вне заметок», работающий и по рабочему столу,
и по окнам. Единственный честный механизм — на время видимости заметок
расширить input region на весь экран своим chrome-актёром и обрабатывать
клики, до которых не добрался никто выше стеком.

## Следствие принятой модели (зафиксировать)

Клик вне заметок съедается подложкой: приложение получает следующий клик.
Это сознательный компромисс light-dismiss (как у меню GNOME), выбран
пользователем 2026-10-23 (ADR-0005).
