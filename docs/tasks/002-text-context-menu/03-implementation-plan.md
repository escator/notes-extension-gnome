# 03. План реализации: контекстное меню текста заметки

Ветка `feat/text-context-menu` от актуального `dev`. Документация — первым
коммитом ветки. Каждая фаза заканчивается рабочим состоянием и одним
логическим коммитом.

## Фазы

### Ф1 — TextHistory: модуль + юнит-тесты (без интеграции)

- Новый `notes@maestroschan.fr/textHistory.js` — API по 02.
- Новый `test/testTextHistory.js` (gjs, образец `test/testLayouts.js`):
  - baseline: undo без изменений → null;
  - одна порция: несколько `onChange` внутри окна → один шаг undo;
  - окно истекло (таймер заглушить инъекцией времени для детерминизма) →
    новый шаг;
  - `boundary()` закрывает порцию;
  - кап глубины: вытеснение старейших;
  - `suspend`: изменения внутри не записываются;
  - undo→redo→новое изменение очищает redoStack;
  - `canUndo/canRedo` на каждом шаге.
- DoD: `gjs test/testTextHistory.js` зелёный; расширение не изменено (модуль
  никем не подключён).

### Ф2 — клавиатурные Undo/Redo (Ctrl+Z / Ctrl+Shift+Z, оба режима)

`noteBox.js`:

- `_loadText` (noteBox.js:634-649): создать `TextHistory` с baseline,
  начальный `set_text` под `suspend`.
- В `_buildNote`: `clutterText.connect('text-changed', …)` → `onChange`
  (текст + позиция курсора, с учётом suspend).
- `_onKeyPress` (noteBox.js:338-348): ветки Ctrl+Z/`KEY_Undo` и
  Ctrl+Shift+Z/`KEY_Redo` → `undo()/redo()` (без смены режима); возврат
  `true`.
- Новые методы `undo()`/`redo()`: `boundary()` → снапшот → `suspend(set_text,
  set_cursor_position)` → `_saveText()`; пустая история — ничего.
- `boundary()` в: `setEditMode`, `_appendClipboardText`, paste-ветке
  `_onKeyPress`.

DoD (живая проверка X11): набор «abc» → Ctrl+Z одним шагом убирает «abc»;
вставка кнопкой заголовка → Ctrl+Z откатывает, в том числе в read-only; Ctrl+Z
на пустой истории — ничего; Ctrl+Shift+Z возвращает отменённое, новое
редактирование очищает redo; файл на диске синхронен после каждой
отмены/возврата; лог чист (кроме известного IME-шума).

### Ф3 — контекстное меню

- Разведка (30–60 мин, до написания кода): локализовать причину FIXME
  `ShellEntry.addContextMenu` (noteBox.js:156) — вывод в журнал 04; выбрать
  способ позиционирования (координаты события vs BoxPointer к entry).
- `menus.js`: класс `NoteTextContextMenu` — все пункты по матрице из 02
  (Вырезать / Копировать / Вставить | Undo / Redo | Выделить всё),
  async-проверка буфера для «Вставить», позиционирование у клика,
  `blockSourceEvents`, привязка жизненного цикла (по 02).
- `noteBox.js`: обработчик `button==3` на `clutterText` + сигнал `popup-menu`;
  ленивое создание меню и `PopupMenuManager` на заметку; `boundary()` перед
  действиями; guard уничтоженной заметки в async-колбэках.
- i18n: строки через `_()`, прогнать `update-and-compile-translations.sh`.

DoD (живая проверка X11): сценарии 1–4, 7, 9–11 из README; правый клик не
сбивает выделение; вставка в позицию курсора; read-only — «Вставить» и
«Вырезать» неактивны; меню закрывается при скрытии/удалении заметки; две
заметки — независимо; лог чист.
