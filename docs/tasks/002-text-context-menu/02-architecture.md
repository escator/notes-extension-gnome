# 02. Концепция: контекстное меню текста заметки

Два новых компонента + интеграция в `NoteBox`. Состав меню и семантика вставки
утверждены пользователем 2026-10-20 (см. 01, раздел решений).

```
clutterText ── text-changed ──▶ TextHistory (снапшоты, коалесцирование)
clutterText ── button-3 / popup-menu ──▶ NoteTextContextMenu
        меню ── действия ──▶ clutterText.copy/paste_clipboard, NoteBox.undo()
NoteBox._onKeyPress ── Ctrl+Z / Ctrl+Shift+Z ──▶ undo()/redo() (оба режима)
```

## Компонент 1: TextHistory (новый модуль `textHistory.js`)

Чистая логика без shell-зависимостей — тестируется gjs-ом по образцу
`test/testLayouts.js` (причина выделения в модуль).

- Состояние: `undoStack`, `redoStack` — стеки снапшотов `{text, cursor}`;
  `pending` — состояние до текущей «порции» изменений; таймер порции.
- API:
  - `new TextHistory(baseline)` — исходное состояние, стеки пусты.
  - `onChange(text, cursor)` — на каждый `text-changed`; при первом изменении
    порции запоминает `pending` = состояние до порции; таймер (окно 800 мс)
    закрывает порцию: `undoStack.push(pending)`, `redoStack` очищается.
  - `boundary()` — принудительно закрыть порцию; вызывается перед известными
    операциями (вставка кнопкой, пункты меню, вставка с клавиатуры, смена
    режима) и в начале undo.
  - `suspend(fn)` / флаг — не записывать изменения внутри `fn` (начальная
    загрузка текста, восстановление из истории).
  - `undo()` → снапшот или `null`; `redo()` → снапшот или `null`;
    `canUndo()`, `canRedo()`.
  - Кап глубины (50), снизу вытесняются старейшие.
- Незакрытая порция при undo: закрывается `boundary()` — Ctrl+Z сразу после
  набора отменяет всю порцию.
- Хранение только в памяти, на сессию заметки; не персистится.

## Компонент 2: NoteTextContextMenu (в `menus.js`, рядом с NoteOptionsMenu)

- На заметку, лениво при первом открытии; `PopupMenu.PopupMenu` +
  `PopupMenuManager` по образцу `NoteRoundButton.addMenu` (menus.js:223-250).
- Пункты (порядок по конвенции GTK entry-меню): Вырезать / Копировать /
  Вставить — разделитель — Undo / Redo — разделитель — Выделить всё.
- Чувствительность при открытии (матрица):

  | Пункт | Режим чтения | Режим редактирования |
  |-------|--------------|----------------------|
  | Вырезать | неактивен | ⇔ есть выделение |
  | Копировать | ⇔ есть выделение | ⇔ есть выделение |
  | Вставить | неактивен (ТЗ, решение 2026-10-20) | ⇔ буфер непуст (async-проверка) |
  | Undo | ⇔ canUndo | ⇔ canUndo |
  | Redo | ⇔ canRedo | ⇔ canRedo |
  | Выделить всё | ⇔ текст непуст | ⇔ текст непуст |

- Действия: Вырезать → `copy_clipboard()` + `delete_selection()`; Копировать →
  `copy_clipboard()`; Вставить → `paste_clipboard()` (после взятия фокуса);
  Undo/Redo → `NoteBox` + сохранение на диск; Выделить всё → фокус +
  `select_all()`. Перед каждым действием — `boundary()`.
- Открытие: `button-press-event` c `button==3` на `clutterText` (позиция —
  координаты события, не угол entry); дублирующе — сигнал `popup-menu`
  (Shift+F10/Menu, a11y).
- Жизненный цикл: `notify::mapped` заметки → close; destroy заметки/entry →
  destroy меню (паттерн menus.js:30-35); колбэки буфера guard'ят уничтоженную
  заметку.

## Интеграция в NoteBox

- `_loadText`: создать историю, `suspend` на время `set_text` (baseline).
- `text-changed` на clutterText → `onChange(text, cursor)` (с учётом suspend).
- `_onKeyPress` (noteBox.js:338-348): добавить Ctrl+Z/`KEY_Undo` и
  Ctrl+Shift+Z/`KEY_Redo` — в обоих режимах, без смены режима; существующая
  ветка Ctrl+V не меняется.
- `undo()` / `redo()`: `boundary()` → `undo()/redo()` → `suspend(set_text,
  set_cursor_position)` → `_saveText()`.
- `boundary()` перед: `_appendClipboardText`, paste из `_onKeyPress`,
  действиями меню, `setEditMode`.
- `destroy()`: меню уничтожается через свою привязку к destroy entry.

## Отклонённые альтернативы

- **`ShellEntry.addContextMenu`** (апстрим): FIXME «не работает»
  (noteBox.js:156), нет Undo, нет наших правил режимов. Причину FIXME
  локализуем в Ф3, но меню делаем своё; если причина тривиальна — переоценить
  только этот пункт, не концепцию (Undo всё равно свой).
- **Глобальный менеджер меню на всё расширение**: усложняет позиционирование и
  жизненный цикл; per-note лениво — как проверенный NoteOptionsMenu.
- **Undo на диффах (patch-модель)**: оверкилл для заметок; снапшоты строк
  достаточно (заметки малы, кап глубины ограничивает память).
- **Персистенция undo-стека**: не нужна (сессия), усложняет форматы хранения.
