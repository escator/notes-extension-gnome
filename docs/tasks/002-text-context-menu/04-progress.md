- 2026-10-21 — разбор (а), исправлено: источник вставки — не ClutterText, а
  **St.Entry** (`st_entry_key_press_event`, GS 42.9): entry сам вставляет по
  Ctrl+V / Shift+Insert и режет по Ctrl+X, когда
  внутренний ClutterText не обработал событие, **без проверки editable**.
  В mutter 42.9 у ClutterText clipboard-биндингов нет вовсе (только Ctrl+A),
  его `key_press` при !editable сразу PROPAGATE — событие доходит до
  St.Entry; `delete_selection`/`insert_text` — буферные API без editable-гейта.
  До Ф2 вставку в read-only перехватывала ветка перенаправления (return true);
  её удаление открыло путь к St.Entry. Ctrl+C/Ctrl+A в read-only делает тоже
  St.Entry — безвредно, оставлено. Фикс: `_onKeyPress` в read-only глотает
  Ctrl+v/V/Paste и Ctrl+x/X, а также Shift+Insert, до класс-обработчика entry.
  Попутно закрыт латентный баг (существовал и до задачи): Ctrl+X вырезал
  выделение из read-only заметки.
