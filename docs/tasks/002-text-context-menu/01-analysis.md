# 01. Анализ: контекстное меню текста заметки

## Текущее состояние

### Текстовый виджет и режимы

- Текст — `St.Entry` (`noteEntry`, noteBox.js:93) с внутренним `ClutterText`
  (noteBox.js:103-110): `single_line_mode=false`, `line_wrap=WORD_CHAR`,
  `selectable=true` (63c4aca — без этого нет Ctrl+C/Ctrl+A в read-only).
- `editable` и `cursor_visible` управляются режимом в `setEditMode`
  (noteBox.js:274-295). По умолчанию read-only (noteBox.js:145-146); новые
  заметки стартуют в редактировании (`startInEditMode`, noteBox.js:161-163);
  при скрытии всех заметок менеджер принудительно возвращает read-only
  (extension.js:391-397).
- Клик по полю берёт фокус только в режиме редактирования (`_getKeyFocus`,
  noteBox.js:496-501); обработчик `button-press-event` на `noteEntry`
  (noteBox.js:135) не фильтрует кнопку — правый клик тоже поднимает заметку
  наверх (`_redraw`).

### Существующие пути буфера

| Путь | Что делает | Где |
|------|-----------|-----|
| Кнопка «копировать» в заголовке | весь текст заметки → CLIPBOARD | noteBox.js:297-302 |
| Кнопка «вставить» в заголовке | дописывает буфер в конец, **работает в read-only**, сохраняет | noteBox.js:304-331 |
| Ctrl+V в read-only | перехват в `_onKeyPress`: включает редактирование + `paste_clipboard()` (8413260) | noteBox.js:338-348 |
| Ctrl+C, Ctrl+A | нативно для selectable ClutterText в обоих режимах | noteBox.js:108-110 |
| Ctrl+Z | **нет нативной поддержки** — у ClutterText/St.Entry нет undo API; сейчас не делает ничего ни в одном режиме | — |

### Меню-инфраструктура

- `NoteOptionsMenu` (menus.js:20-181) — проверенный в проде паттерн:
  `PopupMenu.PopupMenu(sourceActor, 0.2, St.Side.LEFT)`,
  `blockSourceEvents`, актор добавляется в `Main.uiGroup`, жизненный цикл
  привязан к источнику через `notify::mapped` → close и `destroy` → destroy
  (menus.js:30-35). Ленивое создание и `PopupMenuManager` — в
  `NoteRoundButton.addMenu/popupMenu` (menus.js:223-250).
- FIXME: `ShellEntry.addContextMenu(this.noteEntry)` закомментирован как
  «не работает» (noteBox.js:156). Апстрим-модуль даёт `EntryMenu` с
  Copy/Paste/Select All, async-проверкой буфера и открытием по сигналу
  `popup-menu`. Причина неработоспособности в этом коде нигде не
  зафиксирована — надо локализовать (см. 03, Ф3).

### Сохранение текста

`_saveText` вызывается при выходе из режима (noteBox.js:289-293), при
`_redraw` (503-506), при отпускании перетаскивания (581-585), после вставки
кнопкой (327). Любая новая мутация текста (undo) тоже должна сохранять.

### Опасности из истории проекта

- Destroy при живом key focus — сегфолт shell, фикс e901be2
  (noteBox.js:668-680). Вывод: любые новые акторы/попапы обязаны быть
  привязаны к жизненному циклу заметки.
- Асинхронные колбэки буфера должны guard'ить уничтоженную заметку — паттерн
  уже есть (`_appendClipboardText`, noteBox.js:317-318).
- Клин буфера X11 — баг mutter/MetaSelection, не код расширения (память
  `clipboard-wedge-x11`); протокол разбора — `journalctl --user -b 0
  _COMM=gnome-shell`.
- Шум в логе от IME-assertions при клике по selectable-не-editable тексту
  (mutter clutter-text.c:2235) — известное, не чиним.

## Тонкие места

1. **Конфликт семантики вставки.** ТЗ: в меню «Вставить» неактивен в
   read-only. Существующее поведение Ctrl+V (8413260): включает
   редактирование и вставляет. Решение: 2026-10-20 — сохранить оба
   поведения; **пересмотрено 2026-10-21 — вставка работает только в режиме
   редактирования**: пункт меню неактивен в read-only, ветка
   Ctrl+V-перенаправления в `_onKeyPress` удаляется, Ctrl+V в read-only
   молча игнорируется (нативно для не-editable ClutterText). Исходное
   обоснование 8413260 («молчаливый нооп легко принять за сломанный буфер»)
  закрывается контекстным меню: неактивный «Вставить» делает причину
   видимой.
2. **«Копировать всегда».** Требование «доступна всегда» трактуем как «в обоих
   режимах»; активен пункт только при непустом выделении. Правый клик не
   должен сбивать выделение (ClutterText button 3 не обрабатывает —
   подтвердить живьём, сценарий 7).
3. **Асинхронная проверка буфера.** Чувствительность «Вставить» требует
   `St.Clipboard.get_text` (async-колбэк) — пункт обновляется после открытия
   меню; паттерн `EntryMenu._updateItems` из апстрима.
4. **Undo с нуля.** Стек снапшотов на сигнале `text-changed`; коалесцирование
   порций набора (таймер + явные границы: вставка, пункты меню, смена режима,
   undo); подавление записи при начальной загрузке текста и при восстановлении
   из истории; `text-changed` срабатывает и в read-only (кнопка заголовка
   мутирует текст там) — поэтому undo обязан работать в обоих режимах;
   глубина с капом; стек только в памяти, на сессию.
5. **Позиционирование меню.** `PopupMenu` привязан к source-актору, а entry
   занимает почти всю заметку — меню должно открываться у точки клика
   (координаты события), а не у угла поля.
6. **Жизненный цикл меню.** Актор меню живёт в `Main.uiGroup`, вне дерева
   заметки: без привязки к destroy заметки получим утечку/ошибки. Паттерн
   menus.js:30-35 обязателен; `PopupMenuManager` — один на заметку.
7. **События.** Открытие по `button==3` на `clutterText`/`noteEntry` не должно
   мешать существующим обработчикам (подъём заметки по клику — noteBox.js:135;
   внутренняя обработка button 1 у ClutterText — выделение). Не открывать меню
   при перетаскивании/ресайзе.
8. **i18n.** Новые строки через `_()`; `menus.js`/`noteBox.js` уже в
   POTFILES.in; прогнать `update-and-compile-translations.sh`.
9. **Платформа.** Приёмка на X11 (практика проекта); Wayland-специфики у
   `St.Clipboard`/`ClutterText` в этом функционале нет.

## Неучтённые в ТЗ моменты (решения пользователя, 2026-10-20/21)

- **Выделить всё** в меню — принято (Ctrl+A уже работает нативно; пункт дёшев
  и стандартен для entry-меню).
- **Redo** (Ctrl+Shift+Z) — принято; API истории закладываем с Ф1, UI и
  шорткат — в Ф3.
- **Вырезать** (Ctrl+X) — принято: только в режиме редактирования, активен при
  выделении; реализация — `copy_clipboard()` + `delete_selection()`
  (у ClutterText нет `cut_clipboard`).
- **Открытие с клавиатуры** (Shift+F10 / клавиша Menu, сигнал `popup-menu`):
  дёшево, даёт a11y-паритет с GTK — включено в концепцию.
- **Вставка в read-only** — решение 2026-10-20 (сохранить 8413260)
  пересмотрено 2026-10-21: **вставка только в режиме редактирования**. Пункт
  меню «Вставить» неактивен в read-only; перенаправление Ctrl+V в
  `_onKeyPress` (noteBox.js:338-348) удаляется в рамках задачи. Обоснование
  отмены: неактивный пункт меню делает причину видимой — исходная проблема
  8413260 была в молчаливом ноопе без подсказки.
- **Глубина истории** (кап снапшотов) и окно коалесцирования — параметры
  (предложение: 50 шагов, 800 мс).
