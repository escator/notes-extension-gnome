# 02: Архитектура — свой движок выделения в read-only

Решения пользователя 2026-11-12 (ADR-0007): вариант B — press глотается
как сейчас, выделение делает расширение, фокус не трогается вообще.
В объёме: drag, двойной клик по слову, Shift+клик. Клавиатурные пути
read-only не меняются.

## 1. Инварианты (жёсткие)

- В read-only press по тексту **всегда** возвращается `EVENT_STOP` до
  класс-хендлера — `grab_key_focus` из мышиных путей read-only исключён
  (фикс f051d89 остаётся в силе дословно).
- Ни один новый хендлер не вызывает `grab_key_focus` / `set_key_focus`.
- Режим редактирования не затрагивается: нативный путь целиком.
- Правая кнопка — как была: перехват раньше всего, меню, выделение не
  теряется. Средняя и прочие — глотаются без выделения.

## 2. Жест в NoteBox (noteBox.js)

Состояние: `this._selAnchor` (индекс начала выделения, −1 = нет жеста),
`this._textPressTracker` (свой double-click детектор, §5).

### Press (button 1, !editing) — расширение существующего хендлера

1. `_redraw()` (подъём наверх) — как было.
2. Клик ниже/правее текста клампится в конец текста (§3).
3. Двойной клик (детектор §5) → `wordRange(text, idx)` (§6):
   слово → `set_selection(s, e)`, `_selAnchor = s`, жест вооружён
   (дальнейший drag расширяет от слова); не-слово (пробел/пунктуация/
   конец текста) → выделения нет, жест не вооружается.
4. Shift+клик → расширение от текущего края выделения (§4).
5. Обычный клик → `_selAnchor = idx`, `set_selection(idx, idx)`
   (схлопывание = сброс предыдущего выделения, паритет с нативом),
   жест вооружён.
6. `return Clutter.EVENT_STOP` — как было.

### Motion (новый хендлер на ClutterText)

Только при вооружённом жесте и `!editing`: пересчитать idx и
`set_selection(_selAnchor, idx)` (направление в обе стороны —
set_selection принимает убывающие пары). Мимо жёста —
`EVENT_PROPAGATE`, ничего не делаем.

### Release (новый хендлер)

Снять вооружение, сбросить `_textPressTracker`-состояние драга. Выделение
остаётся как есть. Guards: `this.actor == null`, `!this._editing` —
return без действий.

Защита от потерянного release (чужой grab в системе): жест
перевооружается/снимается на следующем press, «залипшего» движения нет.

## 3. Координатный маппинг (единственная геометрия)

```
[transformed, ax, ay] = clutterText.transform_stage_point(stageX, stageY)
layout = clutterText.get_layout()
[inText, index, trailing] = layout.xy_to_index(ax * Pango.SCALE,
                                              ay * Pango.SCALE)
idx = inText ? Math.min(index + trailing, text.length) : text.length
```

- `transform_stage_point` — координаты в системе самого ClutterText:
  вложенность (entry→entryBox→scrollView), паддинги и скролл учтены;
  layout покрывает весь текст, обрезка в ScrollView — только визуальная.
- `trailing` даёт корректную позицию при клике между символами и на
  границе строки; клик за концом строки/текста → `!inText` → конец
  текста (кламп, README-2).
- Риск: происхождение layout в системе актора. Проверка — приёмка Ф-2;
  если систематический сдвиг — калибровка: смещение вычислить разницей
  `position_to_coords(0)` и вычесть (фолбэк, не штатный путь).
- Пустой текст / текст не загружен: `idx = 0`, set_selection(0,0) —
  безопасно.

## 4. Shift+клик

Точка расширения — существующий край выделения: при `idx >= anchor` —
`set_selection(anchor, idx)`, иначе — «обратная» сторона: если текущее
выделение уже было `[a, b]`, расширяем к ближайшему краю от клика:
`set_selection(anchor, idx)` при драг-модели достаточно (паритет с
нативом оценивается приёмкой Ф-4; усложнение не закладываем).

Состояние «текущего выделения» берётся из `get_selection_bound()` /
`get_cursor_position()` ClutterText — своего дубликата не заводим.

## 5. Двойной клик по тексту — отдельный детектор

Существующий `_isDoubleClick` (задача 005) держит общее состояние
`_lastPressTime/X/Y` для moveBox/resize — смешивать с текстом нельзя
(двойные клики в разных местах будут перекрёстно срабатывать).
Рефакторинг: `_isDoubleClick(event, tracker)` — состояние вынесено в
передаваемый объект; `moveBox`/`resize` продолжают пользоваться общим
трекером, текст получает свой `_textPressTracker`. Пороги те же
(системный double-click time, DBL_CLICK_DIST_PX). Двойной клик по тексту
по-прежнему **не** трогает expand (задача 005 не задета).

## 6. Границы слова — textSelection.js (чистый модуль)

`wordRange(text, index)` → `null | [start, end]`:

- слово-символы: `/[\p{L}\p{N}_]/u` — буквы (в т.ч. кириллица), цифры,
  подчёркивание; дефис/пунктуация — граница;
- клик на не-слове или за пределами текста → `null` (выделения нет) —
  сознательно проще натива, решение п. 3 приёмки;
- кластеры: итерация по `for...of` (code points, не UTF-16-юниты) —
  индексы pango тоже в code points, форматы совпадают.

Тестируется офлайн (gjs -m test/testTextSelection.js), как TextHistory.

## 7. Не поддерживается (сознательно, не дефекты)

- Автоскролл вьюпорта при драге за край — нет и в режиме редактирования
  (натив тоже не скроллит), паритет.
- Тройной клик (строка).
- Клавиатурное выделение в read-only вне матрицы (Shift+стрелки) —
  без фокуса недостижимо, матрица не меняется.
- Копирование мышью-сделанного выделения клавиатурой: Ctrl+C в read-only
  работает только при фокусе (после Select All из меню) — без изменений.

## 8. Стили

`.notesTextField` — новых правил нет до приёмки: тема даёт свои цвета
выделения; если на тёмных кастомных цветах подсветка не читаема —
`selection-background-color` + `selection-color` отдельным коммитом
ветки (03 §5).
