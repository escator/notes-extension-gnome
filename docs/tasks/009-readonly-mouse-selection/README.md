# 009: Выделение мышью в режиме read-only (вариант B)

- Статус: **приёмка зелёная** (2026-11-12, живая на 46.2 X11; п.4 снят
  пользователем — merge по согласованию)
- ADR: [0007-readonly-mouse-selection](../../adr/0007-readonly-mouse-selection.md)
  (accepted, 2026-11-12)
- Ветка: `feat/readonly-selection` (документация — первый коммит ветки)

## Цель

В read-only заметках работает мышиное выделение текста — drag, двойной клик
по слову, Shift+клик — и копирование выделения через контекстное меню, при
этом press по тексту по-прежнему глотается **до** класс-хендлера ClutterText:
`grab_key_focus` в мышиных путях read-only нет вообще (вариант B — решение
пользователя 2026-11-12, см. [01-analysis.md](01-analysis.md) и ADR-0007).
Выделение считается и применяется самим расширением через публичные API
(`get_layout()` / pango `xy_to_index` / `set_selection`), координатный
маппинг — новый чистый модуль `textSelection.js` + геометрия в `noteBox.js`.

Инвариант: фокус и клавиатура редактируемой заметки не затрагиваются ни в
каком сценарии; клавиатурные пути read-only не меняются (Ctrl+C/A — через
существующую матрицу после Select All из меню, вставка в read-only
по-прежнему невозможна — решение 2026-10-21).

## Пользовательский сценарий (приёмка, живая, VM 46 X11)

1. Drag-выделение в read-only: подсветка видна во время драга и сохраняется
   после отпускания; правый клик → Copy; вставка в другой программе даёт
   именно выделенный фрагмент.
2. Точность маппинга: выделение начинается/заканчивается ровно на первом
   символе, на последнем символе строки, на середине перенесённой
   (wrapped) строки; клик ниже последней строки клампится в конец текста.
   Систематического смещения нет (если есть — калибровка по
   `position_to_coords(0)`, 02 §3).
3. Двойной клик: выделяет слово (в т.ч. кириллическое); клик по пробелу или
   пунктуации выделения не даёт; драг после двойного клика расширяет
   выделение от слова.
4. Shift+клик расширяет существующее выделение от его края (клик справа —
   к правому краю, слева — к левому). **Снят пользователем 2026-11-12**
   («да и не надо») — функциональность в ветке остаётся, живой проверки
   не требует.
5. Обычный клик без драга сбрасывает выделение (паритет с нативом).
6. Нет кражи фокуса: пока заметка A в редактировании, drag-выделение на
   read-only заметке B не уводит фокус из A; Ctrl+V в A вставляет в A;
   в журнале нет assertion-пар `clutter_input_focus` от кликов по B.
7. Select All из меню в read-only работает как раньше (grab остаётся),
   Ctrl+C после него копирует весь текст.
8. Режим редактирования — без регресса: нативное drag-выделение, правый
   клик, меню и матрица как были (выборочная перепроверка сценариев
   приёмки 002/003).
9. Прокрученная заметка (текст выше вьюпорта): выделение в видимой части
   и в прокрученной части маппится корректно (transform_stage_point
   учитывает скролл); колёсико по телу заметки скроллит как раньше.
10. Визуал: подсветка выделения читаема на светлом пресете и на тёмном
    кастомном цвете; при необходимости — CSS-правило для `.notesTextField`
    (03 §5).
11. Кнопка «Copy» шапки копирует весь текст (как раньше); выбранный
    вопрос-лимит — тройной клик и автоскролл за край не поддерживаются
    (02 §7), отсутствие — не дефект.
12. По всему чек-листу журнал без новых ошибок.
