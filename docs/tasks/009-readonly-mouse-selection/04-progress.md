## 2026-11-12 — Ф2: textSelection.js

- Коммит 5675a5a. `wordRange` (слово = буквы/цифры/`_`, не-слово → null) +
  `byteOffsetToCharIndex`.
- Вскрылось при проектировании: pango `xy_to_index` даёт **байтовый**
  offset в UTF-8, а `set_selection` ClutterText считает символы — нужна
  конверсия; добавлена в модуль (02 §6 дополнен). Существующий
  `selectAllText` (set_selection(0, text.length)) это подтверждает косвенно:
  работает с кириллицей, т.е. API — символьный.
- Тесты 32/32 офлайн.

## 2026-11-12 — Ф3: движок в noteBox.js

- `_isDoubleClick(event, tracker)`: состояние вынесено в трекер; шапка
  (move/resize) — общий `_dblTracker`, текст — свой `_textDblTracker`
  (перекрёстное срабатывание двойных кликов в разных местах исключено).
- Press в read-only: обычный клик — схлопывание в точке клика (сброс
  предыдущего выделения, паритет с нативом) + вооружение драга; двойной —
  wordRange (не-слово → нет выделения); Shift — расширение от дальнего от
  клика края (без выделения — от позиции курсора). Всегда EVENT_STOP —
  класс-хендлер и его grab_key_focus не выполняются (f051d89 не тронут).
- Motion/Release на ClutterText: только при вооружённом жесте; motion
  пересчитывает индекс и делает set_selection(anchor, idx) (направление
  любое); release снимает вооружение. Движение за пределы заметки
  накрывается implicit grab'ом после press.
- Маппинг `_indexAtStagePoint`: transform_stage_point → xy_to_index
  (Pango.SCALE) → clamp (вне layout = конец текста) → byteOffsetToCharIndex.
- setEditMode снимает жест (защита от переключения режима посреди драга).
- Редактирование не задето: хендлеры при `_editing` сразу
  EVENT_PROPAGATE / не вооружаются.
- Синтакс-проверка gjs (провал только на resource:// вне shell), все
  офлайн-тесты зелёные: smoke 106/106, textHistory 51/51, layouts 82/82,
  textSelection 32/32.
- Новых переводных строк нет — ru 53/53 не трогается; POTFILES.in без
  изменений (в textSelection.js нет строк).

## 2026-11-12 — приёмка (частичная, у пользователя)

- П.1–9, 11–12: работает (функционально: drag, двойной клик по слову,
  меню → Copy). П.10 провален: подсветки нет.
- Root cause (по исходнику mutter gnome-46, clutter-text.c):
  `selection_paint()` открывается `clutter_text_should_draw_cursor` =
  `(editable || selectable) && cursor_visible && has_focus`; в read-only
  курсор скрыт и фокус не берётся → нативная подсветка не рисуется вообще,
  CSS не помогает. Объясняет и отсутствие подсветки у Select All из меню в
  предыдущих задачах.
- Попутно проверено по исходнику: ClutterText в 46 — legacy `paint` vfunc,
  детей не рисует → оверлей-ребёнок ClutterText не годится.

## 2026-11-12 — инцидент live-сессии и два скрытых бага

Пользователь после установки оверлея: заметки вообще не показываются
(ни кнопка, ни хоткей). Цепочка причин, все подтверждены журналом живой
сессии GNOME 46:

1. **manager.js, catch в _createNoteBox: `Main.notify(_(...))` с одним
   аргументом.** В GNOME 45+ `MessageTray.Notification` требует и title,
   и body: вызов с body=undefined бросает
   `Invalid value 'undefined' for property body`, маскирует исходную
   ошибку построения заметки и убивает очередь загрузки/restore.
   Пропущенный пункт порта 008. Фикс: log(e) ДО notify + body=e.toString()
   (порядок важен: иначе следующая ошибка notify снова маскирует).
2. **noteBox.js: `overlay.connect('draw', ...)`** — у St.DrawingArea в 46
   единственный сигнал **'repaint'** (без cairo_t; контекст через
   `area.get_context()`, обязателен `cr.$dispose()` — st-drawing-area.c).
   Исходная ошибка построения, которую маскировал п.1:
   `No signal 'draw' on object 'StDrawingArea'` на каждой заметке.
3. Уроки живой отладки: (а) gnome-shell НЕ переимпортирует модули
   расширения при disable/enable — правки требуют полного рестарта шелла;
   (б) рестарт через `gnome-shell --replace` извне сессии валит всю
   сессию (gnome-session-failed → recovery-экран «отключить расширения» →
   disable-user-extensions=true → все пользовательские расширения
   (~/.local) не включаются: 5 шт. висели в INITIALIZED; восстановлено
   `gsettings set org.gnome.shell disable-user-extensions false`). В
   следующий раз — только ALT+F2 r пользователем.

Оба фикса установлены в живую копию; финальная проверка — после ALT+F2 r.

## 2026-11-12 — приёмка п.10 доведена до зелёного (живая, GNOME 46.2, мной по X11)

Цепочка находок (каждая подтверждена журналом/скриншотами x11grab):

1. Подсветка не рисуется — root cause должен_draw_cursor (§8, см. выше) →
   свой оверлей.
2. `'draw'` у St.DrawingArea не существует → `'repaint'` + `get_context()`
   (e259571).
3. Оверлей в вертикальном BoxLayout ложился ПОД текст → Clutter.BinLayout
   стек (1f48ccd). Контрольный эксперимент (красная маркерная плашка на
   каждой заметке + `sel repaint` логи) подтвердил: пайплайн рисует.
4. Подсветка исчезала при драге за конец строки: pango даёт `inText=false`,
   наш кламп возвращает text.length, а **ClutterText хранит «конец буфера»
   как -1 в selection_bound/cursor_position** — оверлей читал это как пустое
   выделение (меню Copy при этом работало). Фикс: нормализация -1 → длина
   текста перед проверками (f521f8e).
5. Клики правее ~самой длинной строки не доходили до хендлеров: **актор
   ClutterText шириной со свою самую длинную строку**. Press/motion/release
   перенесены на noteEntry (вся текстовая область, события текста всплывают
   наверх) (c596fa5).
6. Живой чек мной: drag-выделение многострочное с подсветкой ✓, драг за
   конец строки → выделение до конца текста с подсветкой ✓, двойной клик →
   слово подсвечено ✓, меню Copy → в буфере 'HOMESERVER' ✓, клик в бывшую
   мёртвую зону сбрасывает выделение ✓, журнал чист ✓.
7. Shift+клик: синтетический shift через XTest в mutter не регистрируется
   в состоянии события — пункт отдан пользователю на живую проверку.

Инструменты: gnome-shell НЕ переимпортирует модули при disable/enable
(рестарт обязателен); ReloadExtension объявлен в DBus, но не реализован в
46; диагностический цикл — правка → cp в установленную копию → ALT+F2 r →
journalctl + скриншоты x11grab; контрольно-экспериментальный приём
(маркерная отрисовка + property-хуки со стеками) закрыл вопрос за два
рестарта.
