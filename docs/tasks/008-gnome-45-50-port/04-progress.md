- **2026-10-24. НАЙДЕНА ПРИЧИНА «откатов к апстриму» (важно для Ф4).**
  Симптом пользователя: после перезапуска шелла расширение возвращается
  к апстримному виду, помогает только `./install.sh` + Alt-F2. Механизм
  (по коду работающего шелла 42.9, gresource extensionSystem.js /
  extensionDownloader.js): gnome-shell при каждом старте POST'ит на
  `extensions.gnome.org/update-info/` версии ВСЕХ user-расширений; у форка
  uuid совпадает с опубликованным апстримом, «2.1» < 23 → EGO помечает
  `upgrade`, шелл скачивает апстримный zip и кладёт в
  `~/.local/share/gnome-shell/extension-updates/notes@maestroschan.fr/`
  (в журнале пойман `unzip -uod` 13:44:51); при СЛЕДУЮЩЕМ старте
  `_installExtensionUpdates()` безусловно удаляет установленную папку и
  переносит туда staged-содержимое. `downgrade` обрабатывается так же,
  как `upgrade` — повышение версии форка НЕ защищает; поле `_generated`
  не проверяется; проверки нет только если нет `org.gnome.Extensions` /
  `ExtensionManager` desktop-файлов (updatesSupported). Локальная мера:
  перед КАЖДЫМ рестартом шелла
  `rm -rf ~/.local/share/gnome-shell/extension-updates/notes@maestroschan.fr`.
  Долговременное решение — свой uuid форка (данные не переезжают: DATA_PATH
  в common.js захардкожен отдельно от uuid); нужно решение пользователя
  до релиза 3.0 (Ф4/ADR-0006), иначе заморозка 2.1 и будущие ручные
  установки 3.0 у пользователей будут сноситься апстримом с EGO так же.
