## Журнал

- **2026-10-24.** Задача создана: аудит кода против гайдов GNOME Shell
  45–50 (01), архитектура порта (02), план Ф0–Ф4 (03). Решение —
  [ADR-0006](../../adr/0006-gnome-45-50-port.md) (accepted пользователем,
  реализация отложена). Тестирование 45+ — gnome-shell-pod (решение
  пользователя). Коммит документации — первым коммитом ветки задачи при
  старте реализации.
- **2026-10-24.** Контейнерный прогон текущего кода на **GNOME Shell
  44.9** (образ `ghcr.io/schneegans/gnome-shell-pod-38`, контейнер
  остановлен после теста). Результаты: gjs-смок 239/239 (82+51+106) под
  gjs 1.76.2; install → enable → State ENABLED; иконка панели; меню
  правым кликом (New note / New from Clipboard / Filter by color +
  свотчи / Reset filter / Settings); создание заметки меню, ввод текста,
  коммит ✓; персистентность disable→enable (текст выжил); хоткей
  `<Super><Alt>n` — показать/скрыть; prefs — **упали** (баг из 01 §5,
  `load_from_data`), фикс `(css, -1)` применён в контейнере — окно,
  вкладки Settings и About отрисовались. Итог: 44 годен для legacy-диапазона
  только с фиксом Ф0. Замечания без блокировки: после enable заметки
  восстанавливаются скрытыми (видимость сессионная — семантика, не баг);
  About на GTK 4.8 со скроллбаром (косметика); «New from Clipboard» серый
  при пустом буфере — корректно. Скриншоты — `tmplog/gnome44-*.png`.
  Хозяйственные заметки для локальных прогонов: podman на этой машине
  требует `env -u LD_LIBRARY_PATH` (LD_LIBRARY_PATH из AppImage ZCode
  валит podman); `set-env.sh` в контейнере делает `eval "$@"` и ломает
  вложенные кавычки `bash -c` — сложные команды подавать скрипт-файлами
  через `podman cp`; `gsettings` схем расширения видит только с
  `GSETTINGS_SCHEMA_DIR=<dir расширения>/schemas`.
