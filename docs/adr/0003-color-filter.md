# ADR-0003: Фильтр заметок по цвету (один пресет, сессионный)

- Статус: accepted (пользователь, 2026-10-21 — все решения в обсуждении идеи;
  одобрение концепта — тот же день)
- Дата: 2026-10-21
- Задача: [tasks/004-color-filter](../tasks/004-color-filter/README.md)

## Контекст

Цвета заметок используются как категории, но управлять видимостью по цвету
нельзя: показ/скрытие бинарно и глобально (`_notesAreVisible`,
extension.js:391–447), индивидуального скрытия нет. При этом палитра закрыта
(8 пресетов `PRESET_COLORS`, дефолт = beige), так что цвет — надёжный ключ
группировки. Анализ и точки расширения:
[tasks/004, 01-analysis.md](../tasks/004-color-filter/01-analysis.md).

## Решение

1. **Фильтр — ровно один пресет**: заметка проходит ⇔ её `customColor` равен
   `rgb.join(',')` пресета. Категории «другие цвета» нет — UI не создаёт
   цветов вне палитры. Повторный клик по активному свотчу снимает фильтр.
2. **Состояние сессионное, в памяти `NotesManager`**: не в gsettings, не в
   layouts.json; перезапуск shell сбрасывает. Фильтр — «покажи мне сейчас»,
   а не настройка; забытый персистентный фильтр необъяснимо прятал бы заметки.
3. **Инвариант видимости**: заметка видима ⇔ `_notesAreVisible` ∧ проходит
   фильтр. Все переходы — только через `NoteBox.show`/`onlyHide`
   (input-регион chrome); `_showNotes` показывает лишь прошедших.
4. **UI — секция в панельном меню** (не подменю): свотчи 2×4 в порядке
   палитры, активный обведён кольцом `ring`-цвета (приём меню заметки),
   пункт «Сбросить фильтр». Индикация вне меню — точка-бейдж `ring`-цвета
   у иконки панели.
5. **Исключение фильтром — плавное** (~0,3 с fade-out, с предварительным
   выходом из редактирования): мгновенное исчезновение после смены цвета
   читается как баг, а не реакция. Появление при сбросе — мгновенное.
6. **Новые заметки при активном фильтре создаются его цветом** (New note,
   New from Clipboard, путь «нет ни одной заметки»).
7. **Смена цвета видимой заметки переоценивается менеджером** (хук из
   `applyColorAndSave`): не проходит больше — плавное исключение по п. 5.

Детали (методы, фазы, тесты): [tasks/004,
03-implementation-plan.md](../tasks/004-color-filter/03-implementation-plan.md).

## Альтернативы (отклонены)

- Мультивыбор цветов — перегруз UI и семантики, не нужен (решение
  пользователя).
- Приглушение (dim) вместо скрытия — read-only текст нечитаем, заметка
  ловит клики.
- Подменю вместо секции — лишний клик; секция видна сразу при открытии.
- Персистенция фильтра (gsettings/layouts.json) — см. решение п. 2.
- Категория «Другие» для вне-палитровых цветов — таких цветов не существует.
- Кнопка скрытия отдельной заметки — кандидат на будущее, вне рамок.

## Последствия

- Положительные: контур «цвет = категория» замкнут (группировка → фильтр);
  дёшево — на существующих show/onlyHide и палитре; фильтр не касается
  диска и раскладок мониторов.
- Отрицательные / принятые риски: легаси-цвета вне палитры (до редизайна)
  скрываются любым фильтром — спасение сбросом; забытый фильтр удивляет
  («заметок половина») — компенсируется бейджем и кольцом; fade-out — первая
  анимация в проекте, новый класс потенциальных багов (гонки с
  глобальным hide, opacity после показа).
