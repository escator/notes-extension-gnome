# ADR-0005: Клики как источник видимости — двойной клик по значку и световое отклонение

- Статус: accepted (пользователем, 2026-10-23); п. 2 (подложка)
  **отменён** пользователем 2026-10-24 — живой фейл 007-1 на X11
  (root cause не найден), фича признана слишком дорогой и удалена
- Дата: 2026-10-23
- Задачи: [`../tasks/006-panel-double-click/`](../tasks/006-panel-double-click/),
  [`../tasks/007-click-outside-dismiss/`](../tasks/007-click-outside-dismiss/) (cancelled)

## Контекст

Перед релизом нужны две фичи: (1) двойной клик по значку панели создаёт
заметку при сохранении одиночного клика как toggle; (2) клик вне заметок
скрывает их, с переключателем в настройках (по умолчанию включено).

Ограничения (проверено по исходникам gnome-shell 42.9, X11):

- одиночный и двойной клики неразличимы в момент первого нажатия;
- input region оверлея на X11 — union chrome-прямоугольников
  (`layout.js _updateRegions` → `global.set_stage_input_region`): клики по
  пустому столу/окнам до stage не доходят, пассивный capture их не видит;
- chrome-актёры вставляются `addChrome` под `top_window_group`; при
  `Main.modalCount > 0` input region сбрасывается целиком.

## Решение

1. **Задержка одиночного клика.** `_onButtonPressed` планирует
   `_toggleNotes` через `Clutter.Settings:double-click-time` мс; второй клик
   в этом окне отменяет таймер и создаёт заметку (режим редактирования,
   цвет активного фильтра, заметки показаны). Горячая клавиша и все прочие
   входы в `_toggleNotes` отменяют пару первыми строкой — мгновенного
   toggle для них это не меняет.
2. **Подложка light-dismiss.** Пока заметки видимы и включена настройка
   `hide-on-click-outside` (b, default true) — невидимый реактивный
   `Clutter.Actor` на весь stage, в chrome, прижатый непосредственно над
   `window_group` (ниже заметок, значка, панели, меню, модалок). Его
   `button-press-event` отменяет пару (1) и вызывает `_hideNotes`, клик
   съедается (`EVENT_STOP`). Включение/выключение — через
   `_updateClickCatcher` из `_showNotes`/`_onlyHideNotes`/`changed::` и в
   `destroy`.

Оба решения связаны: dismissal отменяет отложенный toggle — иначе заметки
возвращаются через ~0,4 с после скрытия подложкой.

**Отмена п. 2 (2026-10-24).** Smoke-фаза 7 была зелёной, но живая приёмка
007-1 провалилась: при включённой настройке клик по пустому столу заметки
не скрывал. Код соответствовал исходникам shell 42.9 (`addChrome`, стек,
input region), root cause по горячим следам не найден; пользователь
остановил задачу как слишком дорогую, код 007 удалён из ветки. П. 1 (006)
не затронут и принят живой приёмкой; сценарий 6 приёмки 006 (связка с
подложкой) исчез вместе с фичей.

## Альтернативы (отклонены)

- Мгновенный toggle с откатом второго клика — моргание заметок в паре.
- `event.get_click_count()` Clutter — задержку одиночного всё равно держать
  самому; свой таймер детерминирован и тестируется smoke-харнессом.
- Пассивный capture на stage — на X11 не видит клики по столу/окнам, фича
  не работает.
- Подложка на уровне панели/над заметками — съедает клики панели и значка.
- Полноэкранный актор без `addChrome` — без input region на X11 мёртв.

## Последствия

- Положительные: обе фичи работают одинаково на X11 и Wayland; панель,
  меню и диалоги сохраняют своё поведение без списков исключений; каждый
  клик вне заметок даёт ровно один эффект — скрытие (как toggle).
- Отрицательные / принятые риски: (а) одиночный toggle по значку отвечает с
  задержкой системного таймаута двойного клика — принято осознанно;
  (б) пока заметки видимы, первый клик вне их уходит на скрытие
  (окно/стол получают следующий) — световое отклонение, как у меню GNOME;
  (в) во время модалок shell сбрасывает input region целиком — поведение
  системное, после модалки регион восстанавливается `modalEnded()`.
