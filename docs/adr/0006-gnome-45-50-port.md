# ADR-0006: Поддержка GNOME Shell 45–50 — заморозка legacy-релиза (42–44) и ESM-порт

- Статус: accepted (пользователем, 2026-10-24); реализация отложена
- Дата: 2026-10-24
- Задача: [`../tasks/008-gnome-45-50-port/`](../tasks/008-gnome-45-50-port/)

## Контекст

Форк готовится к публикации на EGO. `metadata.json` заявляет `shell-version:
40–44` — наследие апстрима: реально подтверждён только 42.9 (X11); 40/41
сломаны (prefs форка рассчитан на GTK4, а в 40/41 окно настроек строится на
GTK3).

GNOME Shell 45 (официальный гайд портирования) требует: ESM-импорты вместо
`imports.*`; `extension.js` — класс, унаследованный от `Extension`, с
`enable()`/`disable()`; `prefs.js` — класс `ExtensionPreferences` с
`fillPreferencesWindow()`. Форматы взаимоисключающие: один файл не может быть
одновременно скриптом (≤44) и ESM (45+). Версии 46–50 по аудиту кода
удаляемых API не задевают (см.
[01-analysis.md](../tasks/008-gnome-45-50-port/01-analysis.md)).

Живая машина разработки — 42.9 X11: live-приёмка 45+ на ней невозможна.
Для тестирования выбран [gnome-shell-pod](https://github.com/Schneegans/gnome-shell-pod)
— контейнеры xvfb с каждой версией Shell, пригодны для GitHub Actions
(решение пользователя, 2026-10-24).

## Решение

1. **Два релиза.** Текущее состояние — финальный legacy-релиз:
   `shell-version` → `["42","43","44"]` (40/41 снять), тег `v2.1`, zip
   собирается `build-a-zip.sh`. Multi-versioning EGO сам раздаёт этот zip
   оболочкам ≤44. Legacy после заморозки не развивается.
2. **dev — ESM-порт на 45+**: классы `Extension`/`ExtensionPreferences`,
   относительные импорты, `resource:///…` для shell-модулей. Версия 3.0.
   Состав замен — в плане задачи (Ф1/Ф2).
3. **Тестирование 45+ — только gnome-shell-pod**: для каждой заявляемой
   версии: установка zip в контейнер, enable без ошибок в journal, gjs-смок
   под GJS контейнера. Версия попадает в `shell-version` только после
   зелёного прогона. Живая приёмка UI — опционально на VM (Wayland), не
   блокирует.
4. **Данные и поведение не меняются**: формат `N_state`, `layouts.json`,
   функциональность — это порт инфраструктуры, не фича.

## Альтернативы (отклонены)

- Один универсальный `extension.js` — технически невозможно: `export` в
  не-модуле — синтаксическая ошибка, а 45+ требует default export.
- Сохранить 40–41 — prefs форка на GTK4 там не работает.
- Отказаться от ≤44 совсем — пользователи старых оболочек теряют расширение;
  заморозка через multi-versioning EGO бесплатна.
- Обязательная живая приёмка на VM как условие публикации — дорого; CI-смок
  покрывает работоспособность, визуальная приёмка — опционально.

## Последствия

- Положительные: один формат кода после порта; 46–50 практически бесплатны
  (аудит); CI-матрица ловит регрессии на всех заявленных версиях; честные
  `shell-version` для EGO.
- Отрицательные / принятые риски: legacy-тег существует как замороженная
  точка (не развивается — риска нет); вид окна настроек на Adw проверяется
  только в контейнере/VM — риск вёрстки About (496×405) принят;
  gnome-shell-pod может отставать от свежих Shell — тогда версия просто не
  заявляется; привычная X11-live-приёмка для 45+ недоступна — ритуалы
  переносятся в Wayland/контейнеры.
