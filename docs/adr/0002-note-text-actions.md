# ADR-0002: Собственные текстовые действия заметки (меню, история, клавиатура)

- Статус: accepted (пользователь, 2026-10-20 — меню/история; 2026-10-21 — вставка только в редактировании и полный отказ от нативной клавиатурной обработки)
- Дата: 2026-10-21
- Задачи: [tasks/002-text-context-menu](../tasks/002-text-context-menu/README.md), [tasks/003-own-keyboard-text-actions](../tasks/003-own-keyboard-text-actions/README.md)

## Контекст

Заметка — это chrome-актор с `St.Entry`, который в GS 42 ведёт себя необозримо:
у внутреннего `ClutterText` нет clipboard-биндингов вовсе (при `!editable`
`key_press` сразу PROPAGATE), а `St.Entry` (`st_entry_key_press_event`) без
проверки `editable` вставляет по Ctrl+V/Shift+Insert и режет по Ctrl+X
(`delete_selection`/`insert_text` — буферные API без гейта). Итог живого теста
002: Ctrl+V вставлял в read-only, Ctrl+X вырезал из read-only; апстримный
FIXME `ShellEntry.addContextMenu` «doesn't work» с 2020 года. Undo-библиотеки
у ClutterText нет. Полный разбор: [задача 003, 01-analysis.md](../tasks/003-own-keyboard-text-actions/01-analysis.md).

## Решение

1. **Своё контекстное меню** (`NoteTextContextMenu`): Вырезать / Копировать /
   Вставить — Undo / Redo — Выделить всё; чувствительность по матрице режимов;
   не `ShellEntry.addContextMenu` (нет Cut/Undo/Redo, нет правил режимов).
2. **Своя история отмен** (`textHistory.js`): снапшоты `{text, cursor}`,
   коалесцирование порций, `boundary()`/`suspend()`, кап 50; без персистенции.
3. **Вставка только в режиме редактирования** (пересмотр 8413260,
   2026-10-21): Ctrl+V и пункт меню в read-only неактивны/глотаются и не
   переключают режим.
4. **Полный отказ от нативной клавиатурной обработки текстовых клавиш**
   (2026-10-21): все клавиши набора (Ctrl+V/Shift+Insert, Ctrl+C, Ctrl+X,
   Ctrl+A, Ctrl+Z, Ctrl+Shift+Z, KEY_Undo/KEY_Redo/KEY_Paste/KEY_Cut)
   перехватываются в `NoteBox._onKeyPress` раньше класс-обработчиков и
   исполняются собственными методами; нативный путь (St.Entry/ClutterText)
   для этих клавиш больше не участвует ни в одном режиме.
5. **Общий слой действий**: меню и клавиатура вызывают одни и те же методы
   `NoteBox` (копирование/вырезание/вставка через `St.Clipboard` +
   `insert_text`/`delete_selection`); расхождений в поведении нет.
6. **Сопоставление клавиш независимо от раскладки**: keyval (латиница) ИЛИ
   hardware keycode (физическая клавиша) — комбинации работают на русской
   раскладке.

Клавиатурные пункты 4–6 реализуются в задаче 003; меню и история — задача 002.

## Альтернативы (отклонены)

- `ShellEntry.addContextMenu` — FIXME апстрима с 2020, нет Cut/Undo/Redo,
  нет матрицы режимов, позиция у края entry.
- Нативная вставка St.Entry в режиме редактирования + глотание в read-only
  (затычка ed573d5) — работоспособна, но поведение необозримо (см. контекст),
  и Ctrl+C/X/A остаются зависимыми от недокументированных веток St.Entry.
- Смена режима при Ctrl+V в read-only (8413260) — отмена решена
  пользователем: неактивный пункт видит причину, автопереключение — нет.

## Последствия

- Положительные: предсказуемая клавиатура во всех режимах; undo/redo в обоих
  режимах; меню и клавиатура неразличимы по результату; независимость от
  будущих изменений St.Entry.
- Отрицательные / риски: keycode-матчинг — эвристика (покрыта union-схемой
  с keyval); IM-preedit во время вставки; клин буфера mutter/X11 остаётся
  внешним ограничением ([[clipboard-wedge-x11]]); свои обработчики надо
  поддерживать при смене GS.
